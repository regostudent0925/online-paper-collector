# 온라인 폐지줍기 - 티끌모아 태산

실제 운영 앱의 소스 저장소입니다. HTML/CSS/JavaScript 화면과 로컬 Node.js 서버, Chrome 보조 확장으로 구성됩니다. 행사 참여·로그인·포인트 받기·동의는 사용자가 직접 수행합니다.

## 실행

Node.js 22 이상, 외부 npm 의존성·API 키 불필요.

```powershell
npm run setup
npm run choices
```

http://127.0.0.1:4179/ 에서 오늘의 이벤트·Npay·참여 통계를 확인합니다. setup은 data 파일이 없을 때만 공개 조사 예제를 복사하며 기존 데이터·참여 기록을 덮어쓰지 않습니다. 예제는 과거 확인 자료이므로 현재 접수·지급 조건을 다시 확인해야 합니다. 실제 기록이 없는 새 설치의 통계는0입니다.

## 기능

- 이벤트 게시판: 정답 즉시 표시, 상세 조건 펼치기, 상태 선택·저장
- Npay: 검색·정렬·완료 목록·재적립 확인 전 재노출 방지
- 보조 확장: 사용자가 포인트 받기 또는 지정된 기참여 안내 확인을 누른 뒤5초에 소유 탭만 닫고 로컬 완료 보관
- 통계: 한국시간 일간·주간(월요일 시작)·월간·연간 및 CSV. 표시 포인트를 지급되었다고 가정하되 기참여 안내로 보관한 적립일 미확인 항목은 새 기간 합계에서 제외

확장 설치는 browser-helper/README.md 참조. 새 권한은 별도 사용자 승인이 필요합니다. 기존 일일 예약은 Codex 앱의 로컬 자동화이며 GitHub/Vercel만으로 실행되지 않습니다. 예약 식별자·현재 설정은 저장소에 포함하지 않았습니다.

## 변경 관리

```powershell
npm run git:check
npm run git:publish -- "변경 내용을 한 줄로 설명"
```

publish는 허용된 코드·문서만 스테이징 → 경로·대표 비밀정보 패턴 점검 → 전체 테스트 → 변경 중인 파일 여부 점검 → 커밋 → origin의 현재 브랜치 업로드 순서입니다. Git 인증이 준비되어 있어야 합니다. 강제 push는 하지 않으며 실패하면 오류를 확인하고 중단합니다. 파일을 저장하는 즉시 무조건 업로드하는 감시 작업은 없습니다.

단독 테스트: `npm test`

## 보관 경계

추적: src, ui, browser-helper, test, 명시한 tools, 설정·문서, examples/data의 공개 조사 예제.
제외: 실제 data·state(참여 이력/통계 원본)·verification·output·exports·automation-config.json·automation-existing.json·TASK 파일·비밀정보·의존성.

참여 기록은 이 컴퓨터의 state 폴더에 남습니다. GitHub는 개인 참여 기록의 백업이 아닙니다. 로컬 데이터의 별도 보관은 사용자가 관리합니다. examples/data에는 사용자 참여 표시·확인 이력·개인 선택을 제거한 공개 조사 자료만 포함했습니다.

이 공개 운영 코드 저장소는 공개 v0 디자인 사본(online-paper-collector-design)과 분리됩니다. 디자인 사이트의 v0 변경은 운영 코드로 자동 병합하지 않습니다.


## Vercel 웹 배포

GitHub 운영 저장소의 main 변경을 Vercel에 자동 배포하도록 연결합니다. 저장 → 검증·커밋 → GitHub 업로드 → Vercel 빌드 → 새 웹 화면 순서이며 파일 저장만으로 배포되지 않습니다.

`npm run build`는 dist에 정적 웹 미리보기를 만듭니다. Vercel은 vercel.json의 buildCommand/outputDirectory를 사용합니다. 빌드는 published/catalog.json의 검증된 공개 사본을 읽으며, 사본이 없는 새 설치에서는 examples/data 예제를 사용합니다. 실제 data/state는 배포 입력으로 읽지 않습니다. 배포 시 개인 상태는 비워 두고, 웹 방문자의 상태 저장·통계 계산은 각자의 브라우저에서 수행합니다. Chrome 자동 닫기는 기존 로컬 주소 전용입니다. 매일 조사 뒤 public:export로 허용된 공개 필드만 내보내고 GitHub에 업로드하면 Vercel에 자동 반영됩니다. 기존 로컬 오전9시 조사 예약을 클라우드 실행으로 바꾸지는 않습니다.

Vercel 프로젝트: https://vercel.com/lee-9bfb/online-paper-collector

## 매일 공개 목록 갱신

`npm run public:export`는 로컬 조사자료에서 검증된 공개 필드만 `published/catalog.json`으로 내보냅니다. 원본 객체의 알 수 없는 필드·참여 선택·이력·계정·완료·통계·완료ID 기반 재적립 증거를 제외합니다. state 폴더는 열지 않으며, 의심 개인정보 텍스트·허용되지 않은 URL 쿼리는 오류로 중단합니다. 변경이 없으면 같은 사본을 다시 저장하거나 커밋하지 않습니다. GitHub에는 이 파일 한 개만 일일 갱신합니다. 인증은 연결된 GitHub 커넥터 또는 기존 Git 인증을 사용하며 새 토큰을 소스에 저장하지 않습니다.

매일9시 기존 Codex 작업에 내보내기→검사→GitHub main 업로드→Vercel Ready 확인 절차를 추가했습니다. PC와 Codex가 켜져 있어야 새 조사를 수행합니다. PC가 꺼져 있어도 이미 배포된 사이트는 열립니다.

공개 웹은 방문자 공통 목록입니다. 개인별 참여완료·미관심 제외 결과를 공개 목록에 반영하지 않습니다. 공개 데이터에는 개인 상태가 없으며, 웹 화면은 방문자 브라우저의 기록을 덧붙여 개인별로 필터링·집계합니다. 실제 개인정보와 개인 선택은 GitHub·Vercel 서버에 업로드하지 않습니다. 새 필드를 공개하려면 src/public-catalog.mjs의 허용 목록과 검사를 명시적으로 수정해야 합니다.

## 로그인 없는 공개 홈페이지의 개인 기록

Vercel 방문자는 참여 상태, Npay 완료, 일간·주간·월간·연간 통계를 해당 사이트의 브라우저 localStorage에 저장한다. 저장 키는 paper-collector-personal-v1이며 이름·전화번호·네이버 계정·잔액은 수집하지 않는다. 표시 포인트를 지급된 것으로 가정하며 실제 지급을 조회하지 않는다. 브라우저 프로필·도메인이 다르면 별도 기록이고, 브라우저 데이터 삭제/시크릿 종료 시 기록이 사라질 수 있다. 같은 브라우저 프로필을 함께 쓰는 사람끼리는 기록이 구분되지 않는다.

참여 통계 → 내 기록 백업에서 JSON 내보내기 또는 파일 가져오기를 사용한다. 가져온 파일은 서버로 업로드하지 않는다. 최대5MB, 허용 필드·시각·선택값·금액·버전을 검사한 뒤 건수를 보여주고 사용자가 병합을 눌러야 저장한다. 기존 기록은 삭제하지 않으며 최신 이벤트 상태·최초 참여 신고일·동일 Npay 광고 완료를 병합한다. 중복 파일은 적립액을 중복 가산하지 않는다. 목록에서 사라진 완료 항목도 보존하고 새 회차의 이벤트는 다른 키로 구분한다. 브라우저 완료 광고는 공식 재적립 증거를 연결할 방법이 없어 보수적으로 재노출하지 않는다.

공개 웹에서는 이벤트 상태를 선택 후 저장하고 Npay는 직접 참여한 뒤 참여완료 버튼을 누른다. 링크 열기만으로 완료하지 않는다. 자동 탭 닫기와 기존 자동 분류는 127.0.0.1의 승인된 Chrome 확장 전용으로 유지한다. 기존 로컬 기록은 자동 업로드하거나 공개 웹으로 옮기지 않는다.

개인 데이터는 브라우저와 사용자가 내려받은 파일에만 남는다. 백업은 참여 내역을 포함하므로 공개 저장소에 업로드하지 않는다. Git 업로드는 소스·테스트·검증된 공개 목록만 허용하고 data/state/verification/dist 및 임의 백업 파일은 계속 제외한다. Vercel 배포 파일에는 빈 통계만 들어가며 실제 개인 통계는 브라우저에서 계산한다. 외부 전송 코드·분석 스크립트·사용자 기록 API는 추가하지 않는다.

## GitHub Codespaces 미리보기

`codespaces-deploy` 브랜치에서 Codespace를 만들면 공개용 정적 빌드를 생성한 뒤 4179 포트를 자동으로 엽니다. 공개 빌드는 `published/catalog.json`만 읽으며 `data/`, `state/`, 개인 참여 기록, 쿠키와 토큰을 포함하지 않습니다. 참여 상태와 통계는 방문한 브라우저의 로컬 저장소에만 남습니다.

1. 저장소에서 **Code → Codespaces → Create codespace on codespaces-deploy**를 선택합니다.
2. 브라우저에 열린 4179 포트에서 화면을 확인합니다.
3. 다른 사람과 임시로 공유할 때만 **PORTS → 4179 → Port Visibility → Public**을 선택합니다.

Codespace를 중지하거나 삭제하면 전달 URL도 더 이상 동작하지 않습니다. 상시 공개 주소가 필요하면 기존 Vercel 배포를 사용합니다.


## 이메일 인증 로그인 (연결 설정 필요)

2026-10-20 요청으로 이메일 OTP 로그인과 계정별 참여 기록을 추가했습니다. 비로그인 브라우저 기록과 로그인 계정 기록은 분리됩니다. 참여했음 저장이 서버에서 확인되면 참여완료 목록과 개인 통계에 즉시 반영됩니다. 링크를 여는 것만으로 참여완료가 되지는 않습니다.

1. Supabase 프로젝트에서 `src/auth/schema.sql`을 SQL Editor로 실행합니다. 본인 행만 읽을 수 있고, 저장 RPC는 인증된 사용자 ID와 revision을 검사합니다. 익명 사용자는 계정 기록에 접근할 수 없습니다.
2. Authentication에서 이메일 인증을 활성화하고 **Magic Link 이메일 템플릿에 `{{ .Token }}`**을 넣어 인증번호를 전달합니다. 실제 사용자에게 메일을 보내려면 해당 프로젝트의 SMTP 발신 설정과 전송 제한을 확인합니다.
3. Vercel 빌드 환경에 `PUBLIC_SUPABASE_URL`과 `PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 설정한 뒤 다시 빌드합니다. 키는 `sb_publishable_` 공개 키만 허용하며 service_role·secret 키는 사용하지 않습니다. Codespaces도 같은 환경변수로 `npm run build`를 실행합니다.
4. 페이지에서 이메일 → 인증번호 → 로그인을 진행합니다. 이름/별명은 선택 입력이며 이메일이 로그인 ID입니다. 여러 기기에서 같은 이메일로 인증하면 같은 기록을 읽습니다. 다른 기기에서 기록을 바꾼 경우 **내 기록 새로 읽기** 후 저장합니다. 충돌 시 덮어쓰지 않습니다.
5. 기존 브라우저 기록을 계정에 넣으려면 **이 브라우저의 기존 기록 가져오기**를 직접 누릅니다. 자동 업로드하지 않으며, 원래 기록도 유지합니다. JSON 백업 병합도 로그인 중에는 본인 계정에 업로드합니다.

인증 토큰과 계정 기록은 페이지 메모리에만 유지합니다. 새로고침·창 종료·만료 후에는 다시 이메일 인증해야 합니다. 이메일/인증번호/토큰은 소스·공개 빌드·GitHub에 저장하지 않습니다. 인증 메일과 계정 데이터는 연결한 Supabase 프로젝트에서 처리하며 유료 서비스 구매는 자동으로 하지 않습니다.

설정이 없으면 로그인 패널에 연결 필요 안내가 표시되고 기존 비로그인 기능은 유지됩니다. 실제 서비스 연결·RLS 적용·이메일 수신·두 계정 접근 격리 검증을 마치기 전에는 운영 로그인 활성화 완료로 간주하지 않습니다. 참고: [Supabase 이메일 OTP](https://supabase.com/docs/guides/auth/auth-email-passwordless), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).
